# Spec 작성

사용자의 요청을 분석하여 `specs/[feature-name]/spec.md` 문서를 작성한다.

## 실행 절차

### 1. 요청 분석
- 사용자의 요청에서 핵심 문제/기능을 파악
- 관련 코드를 탐색하여 현재 상태 파악
- feature-name 결정 (영문 kebab-case)

### 2. spec.md 작성

`specs/[feature-name]/spec.md` 파일을 아래 구조로 작성:

```markdown
# [기능/버그 제목]

## 현재 상태
- 관련 코드의 현재 동작 설명
- 관련 파일 목록

## 문제 정의
- 무엇이 문제인가 / 무엇을 만들어야 하는가

## 요구사항
- [ ] 구체적 요구사항 1
- [ ] 구체적 요구사항 2
- ...

## 접근 방식 비교 (선택)
| 방식 | 장점 | 단점 |
|------|------|------|
| A    |      |      |
| B    |      |      |

→ 선택: [방식] — 이유

## 데이터 흐름 (선택)
관련 데이터가 어떻게 흐르는지 도식화
```

### 3. 사용자 확인
- 작성한 spec을 사용자에게 보여주고 확인 요청
- 수정 요청이 있으면 반영
- **다음 단계**: `/plan` 스킬로 구현 계획 수립
