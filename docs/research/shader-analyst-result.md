# 정맥 셰이더 "구름" 형태 분석 결과

## 1. 문제 요약

정맥(vein) 셰이더가 레퍼런스의 "날카로운 선/촉수" 대신 "구름/안개" 형태로 렌더링됨.

## 2. 원인 분석 — 5가지 복합 요인

### 원인 A: 트레일맵 자체가 이미 과도하게 확산됨 (근본 원인)

**확산 4패스** (`DIFFUSE_PASSES: 4`)가 매 프레임 실행됨. `diffuse_decay.frag.glsl`에서 3x3 평균 블러를 4회 반복하므로, 실질적으로 ~9px 반경의 가우시안 블러에 해당. 이는 에이전트가 만든 좁은 트레일 경로를 매 프레임마다 넓게 퍼뜨림.

**결과**: 정맥 셰이더에 입력되는 트레일맵이 이미 "구름"처럼 퍼진 상태. 아무리 정교한 능선 검출을 해도, 입력 데이터의 공간 해상도가 이미 손실된 상태에서는 날카로운 선을 복원할 수 없음.

**수치 검증**:
- `DECAY_FACTOR: 0.97` → 정상상태 트레일 값 = `deposit / (1 - decay)` = `5 / 0.03` ≈ 167
- 4패스 확산으로 167 수준의 값이 반경 ~9px에 걸쳐 부드럽게 분포
- 이웃 셀과의 차이(ridge)가 매우 작아짐

### 원인 B: 정맥 셰이더의 3x3 블러가 추가 평활화 (악화 요인)

`veins.frag.glsl` 23~30행에서 **STEP=8** 간격의 3x3 블러를 추가로 수행:

```glsl
vec2 texel = (8.0 * zoomFactor) / u_mapSize;  // 8/1500 = 0.00533
for (int dy = -1; dy <= 1; dy++) {
    for (int dx = -1; dx <= 1; dx++) {
        value += texture(u_trailMap, fract(trailUV + vec2(dx, dy) * texel)).r;
    }
}
value /= 9.0;
```

이미 확산된 트레일맵을 반경 8px로 한 번 더 평균내므로, 실질 블러 반경이 ~17px로 확대됨. 이는 좁은 수송 채널의 디테일을 완전히 뭉개버림.

### 원인 C: 능선 검출이 구조적으로 약함 (구름 형태의 직접 원인)

```glsl
vec2 farTexel = texel * 2.0;  // 16px 거리 이웃
float avg = (right + left + up + down) * 0.25;
float ridge = value - avg;
float relRidge = ridge / max(value, 1.0);
float ridgeStrength = smoothstep(0.2, 0.5, relRidge * 3.0);
```

**문제 1 — 검출 범위가 너무 넓음**: `STEP=8` * 2 = 16px 거리의 4방향 이웃과 비교. 이미 확산으로 퍼진 값에서 16px 떨어진 이웃과의 차이는 미미. 넓은 영역이 비슷한 ridge 값을 가져 "구름" 형태가 됨.

**문제 2 — 상대적 ridge(`relRidge`)의 분별력 부재**: 고밀도 영역에서 `ridge/value`는 매우 작은 값. 예: 중심 value=150, 16px 이웃 value=140이면 ridge=10, relRidge=10/150=0.067. `smoothstep(0.2, 0.5, 0.067 * 3.0)` = `smoothstep(0.2, 0.5, 0.2)` ≈ 0.0. 실제 정맥 영역도 거의 0에 가까워, 넓은 영역에서 비슷한 낮은 값이 나옴.

**문제 3 — smoothstep 범위가 부적절**: `smoothstep(0.2, 0.5, ...)` 구간이 너무 좁아서, 대부분의 픽셀이 0 또는 비슷한 낮은 값. 날카로운 구분이 불가능.

### 원인 D: `densityT` 곱이 넓은 영역을 동일 강도로 만듦

```glsl
float densityT = clamp((value - veinMin) / (veinMax - veinMin), 0.0, 1.0);
float alpha = densityT * ridgeStrength * layerAlpha * layerPulse;
```

- `veinMin=25`, `veinMax=120`
- 본체 중심부의 트레일 값은 대부분 25~120 범위에 들어감
- `densityT`가 넓은 영역에서 높은 값(0.5~1.0)이므로, 약한 ridgeStrength도 가시적 alpha를 생성
- 결과: 정맥이 아닌 넓은 본체 영역까지 흐릿하게 보임

### 원인 E: 본체 셰이더가 정맥을 부분적으로 덮음 (가시성 감소)

렌더링 순서 (`SceneRenderer.ts` 258~281행):
1. blob_body (SRC_ALPHA, ONE_MINUS_SRC_ALPHA)
2. veins (SRC_ALPHA, ONE_MINUS_SRC_ALPHA)

정맥이 본체 위에 그려지지만, `BODY_MAX_ALPHA=0.85`로 본체가 거의 불투명. 정맥의 미세한 구조적 차이가 불투명 본체 위에서 더욱 흐릿해짐. 다만 이것은 "구름 형태"의 직접 원인은 아니고, 정맥의 대비를 약화시키는 부수 요인.

## 3. 파라미터 적정성 평가

| 파라미터 | 현재값 | 평가 | 비고 |
|---------|--------|------|------|
| STEP | 8 | **과도** | 블러 반경 8px + 능선 검출 16px = 총 ~33px 범위. 수송 채널 폭(추정 3~10px)보다 훨씬 넓음 |
| RIDGE_SCALE | 3.0 | **부족** | 상대적 ridge가 0.01~0.1 수준이므로 3배해도 0.03~0.3 → smoothstep에 거의 안 걸림 |
| MIN | 25 | 적절 | 배경 노이즈 제거용으로 합당 |
| MAX | 120 | **낮음** | 정상상태 ~167이면 대부분 클램프됨. densityT가 넓은 영역에서 1.0 |
| MAJOR_THRESHOLD | 40 | 적절 | — |
| MINOR_ALPHA | 0.15 | 적절 | 모세정맥 억제 |
| MAJOR_ALPHA | 0.85 | **과도** | 약한 ridge에서도 높은 alpha |
| smoothstep(0.2,0.5) | — | **부적절** | 실제 relRidge*SCALE 분포와 불일치. 대부분 0.0~0.2에 몰려있음 |

## 4. 기술적 제안 — "선/촉수" 형태를 만드는 방법

### 방법 A: 라플라시안/2차 미분 기반 능선 검출 (권장)

현재 "center - 4방향 평균"은 1차 미분 기반 단순 능선. 이를 **Hessian 행렬의 고유값** 기반으로 교체하면 선형 구조(ridge)와 둥근 구조(blob)를 구분할 수 있음.

```
Hessian:
  dxx = (left + right - 2*center) / h^2
  dyy = (up + down - 2*center) / h^2
  dxy = (topRight + bottomLeft - topLeft - bottomRight) / (4*h^2)

eigenvalues:
  lambda1 = 0.5*(dxx+dyy) + sqrt(0.25*(dxx-dyy)^2 + dxy^2)
  lambda2 = 0.5*(dxx+dyy) - sqrt(0.25*(dxx-dyy)^2 + dxy^2)

ridgeness = -min(lambda1, lambda2)  // 큰 음의 고유값 = 능선
```

선형 구조에서는 한 방향으로만 곡률이 크므로 `|lambda1| >> |lambda2|` → ridgeness가 높음.
구름(둥근 구조)에서는 `|lambda1| ≈ |lambda2|` → ridgeness가 낮음.

### 방법 B: 멀티스케일 능선 검출

단일 STEP 대신 여러 스케일(2, 4, 8px)에서 능선을 검출하고, 최대값을 취함. 가느다란 정맥부터 굵은 주정맥까지 모두 포착.

### 방법 C: 3x3 블러 제거 + 확산 패스 수 감소 (가장 간단)

1. 정맥 셰이더의 3x3 블러(23~30행) **제거** — 원본 트레일맵 직접 사용
2. 능선 검출 STEP을 2~3으로 축소 — 좁은 범위에서 날카로운 차이 감지
3. `DIFFUSE_PASSES`를 4→2로 줄이면 트레일맵 자체의 공간 해상도 보존 (단, 시뮬레이션 동역학에 영향)

### 방법 D: 비등방적 확산 (장기 과제)

트레일맵 확산 자체를 등방적 블러에서 **비등방적 확산**(그래디언트 수직 방향으로만 확산)으로 변경. 이렇게 하면 채널 방향으로는 확산되지만 채널을 가로질러는 확산하지 않으므로, 자연스럽게 좁은 선형 구조가 유지됨. 다만 셰이더 복잡도가 크게 증가.

### 방법 E: 별도 "미확산" 트레일맵 유지 (실용적 절충)

- 확산 전 트레일맵을 별도 텍스처에 보관
- 정맥 셰이더는 미확산 텍스처에서 능선 검출
- 에이전트 센서는 기존 확산 트레일맵 사용
- 추가 텍스처 1장 필요 (메모리 비용 낮음)

## 5. 우선순위 제안

| 순위 | 방법 | 난이도 | 효과 |
|------|------|--------|------|
| 1 | **C**: 블러 제거 + STEP 축소 | 낮음 | 즉시 개선, 부작용 있을 수 있음 |
| 2 | **E**: 미확산 트레일맵 분리 | 중간 | 근본적 해결, 시뮬레이션 영향 없음 |
| 3 | **A**: Hessian 능선 검출 | 중간 | 선형 구조 정밀 검출 |
| 4 | **B**: 멀티스케일 | 중간 | A와 결합 시 최상 |
| 5 | **D**: 비등방 확산 | 높음 | 최종 목표, 장기 과제 |

## 6. 핵심 결론

**근본 원인은 트레일맵의 과도한 확산(4패스 3x3 블러)**이 정맥의 공간적 날카로움을 이미 파괴한 것. 정맥 셰이더가 추가 3x3 블러(STEP=8)로 이를 악화시키고, 넓은 범위(16px) 능선 검출이 구름 형태를 만듦.

**가장 효과적인 단기 해법**: 정맥 셰이더의 3x3 블러 제거 + STEP을 2~3으로 축소하여 좁은 범위에서 날카로운 ridge를 검출. 또는 미확산 트레일맵을 별도 유지하여 정맥 검출의 입력 해상도를 근본적으로 개선.

## 7. 추가 분석 — reference-analyst 피드백 반영

> reference-analyst 핵심 발견: 정맥 실폭 2~5px, 경계 1px 내 전환

### Q1. Hessian으로 2~5px 폭의 선을 검출하려면 STEP을 얼마로 해야 하는가?

Hessian 2차 미분에서 `h`(샘플 간격)는 **검출 대상 구조의 특성 폭(characteristic width)의 절반 이하**여야 함. Nyquist 정리의 공간적 해석.

- 목표 정맥 폭: 2~5px
- **STEP = 1** (인접 픽셀): 2px 폭의 가장 가느다란 정맥까지 검출 가능. Hessian의 `dxx = (left + right - 2*center)`에서 h=1이면 2px 폭 ridge의 곡률이 최대.
- **STEP = 2**: 4~5px 폭의 주정맥에 최적. 2px 정맥은 약간 뭉개질 수 있으나 여전히 검출됨.
- **STEP = 3 이상**: 5px 폭 정맥에서 곡률이 약해지기 시작. 2px 정맥은 검출 불가.

**결론: STEP = 1 (미확산 텍스처 사용 시) 또는 STEP = 2 (확산 텍스처 사용 시)**

멀티스케일 조합이 가장 효과적: `h=1`과 `h=2`에서 각각 Hessian을 계산하고 ridgeness의 최대값을 취하면 2~5px 범위 전체를 커버. 추가 texture fetch는 스케일당 5개(center, left, right, up, down + 대각 4개 중 재사용)이므로 총 ~13 fetches. 현재 셰이더의 9+4=13 fetches와 동일.

### Q2. 확산 4패스 후에도 2~5px 선이 남아있는가? (미확산 텍스처 필수 여부)

**수치 분석 — 1D 가우시안 블러의 반복 효과:**

3x3 box 블러 1패스의 유효 가우시안 σ ≈ 0.8px. N패스 반복 시 σ_total = σ * sqrt(N):
- 1패스: σ ≈ 0.8px
- 2패스: σ ≈ 1.1px
- 4패스: σ ≈ 1.6px

가우시안 블러 후 선형 구조의 유효 폭 증가 = 원래 폭 + 2 * σ_total * 2.35 (FWHM):
- 원래 폭 1px (단일 에이전트 트레일) → 4패스 후: 1 + 2*1.6*2.35 ≈ **8.5px**
- 원래 폭 3px (다수 에이전트 수송 채널) → 4패스 후: 3 + 7.5 ≈ **10.5px**
- 원래 폭 5px (주정맥) → 4패스 후: 5 + 7.5 ≈ **12.5px**

**결론: 확산 4패스 후에는 2~5px 선이 8~13px 폭으로 퍼짐. 원래 폭 대비 2.5~4배 팽창.**

이 정도면 ridge 자체는 소실되지 않으나(피크가 여전히 존재), 경계의 날카로움은 완전히 파괴됨. reference-analyst가 요구하는 "1px 내 전환"은 **확산 텍스처에서는 절대 불가능**.

**미확산 텍스처의 필요성:**

| 시나리오 | 정맥 폭 | 경계 전환 | 가능 여부 |
|---------|---------|----------|----------|
| 확산 4패스 + Hessian STEP=2 | ~10px | ~3px gradation | "날카로운 선" 불가, "약간 개선된 구름" |
| 확산 2패스 + Hessian STEP=1 | ~5px | ~2px gradation | 가능하나 시뮬레이션 동역학 변경 |
| **미확산 + Hessian STEP=1** | **2~5px (원본 유지)** | **1px (원본 유지)** | **목표 달성** |

**미확산 텍스처는 사실상 필수.** 확산 패스 수를 줄이는 방법은 Jeff Jones 모델의 에이전트 동역학(센서 응답, 경로 선택)에 직접 영향을 미치므로 위험. 미확산 텍스처는 렌더링에만 영향하고 시뮬레이션에 영향 없음.

### Q3. Additive blend로 전환 시 기존 알파 파이프라인에 대한 영향

현재 렌더링 파이프라인 (SceneRenderer.ts):
```
1. 배경 clearColor (8, 20, 10)
2. 페로몬 등고선: SRC_ALPHA, ONE_MINUS_SRC_ALPHA
3. blob_body: SRC_ALPHA, ONE_MINUS_SRC_ALPHA  → 본체 알파 ~0.85
4. veins: SRC_ALPHA, ONE_MINUS_SRC_ALPHA       → ★ 여기를 변경
5. cubic_glow: SRC_ALPHA, ONE (이미 additive)
```

**정맥을 additive blend(`SRC_ALPHA, ONE`)로 전환하면:**

**장점:**
- 본체의 불투명도(0.85)에 관계없이 정맥 색상이 **더해짐** → 정맥이 본체 "위에 떠 보이는" 효과
- 레퍼런스의 "밝기 차이 2~4배" 재현 가능
- 본체가 불투명해도 정맥이 묻히지 않음

**주의점:**
1. **색상 포화(saturation)**: additive이므로 정맥 + 본체가 1.0을 넘을 수 있음. 본체 색 (220,200,60)/255 ≈ (0.86,0.78,0.24) + 정맥 색 (0.95,0.88,0.35)*alpha → 합이 1.0 초과 시 화이트아웃.
   - **해결**: 정맥의 `fragColor` RGB를 낮추거나, `alpha`를 줄여서 기여량 제한. 또는 `min(result, 1.0)` 클램프 (GPU가 자동 수행).
2. **배경 위 정맥 (본체 밖)**: 본체가 투명한 영역(본체 가장자리 너머)에서 정맥만 돌출되는 경우, additive와 alpha blend 차이 없음 (배경이 어두우므로). 오히려 레퍼런스의 "촉수" 느낌에 부합.
3. **기존 큐빅 글로우**: 이미 `SRC_ALPHA, ONE` (additive)이므로 일관성 있음.
4. **밀집도 뷰 모드**: `viewMode === 'density'`일 때 정맥이 이미 숨겨지므로 영향 없음.

**구체적 변경:**
```typescript
// SceneRenderer.ts, 정맥 패스 (약 270행)
gl.blendFunc(gl.SRC_ALPHA, gl.ONE);  // ONE_MINUS_SRC_ALPHA → ONE
```

**영향 최소화를 위한 보정:**
- 정맥 `MAJOR_ALPHA`를 0.85 → 0.4~0.5로 낮춤 (additive는 더 밝으므로)
- 정맥 색상을 약간 어둡게 조정 (0.95,0.88,0.35) → (0.8,0.7,0.25) 등
- 맥동(pulse)의 최소값(`PULSE_MIN`)을 약간 올림 (additive에서 맥동이 더 극적으로 보이므로)

**결론: additive blend 전환은 안전하며 권장됨.** 기존 파이프라인에 대한 영향은 정맥 레이어에 국한되고, 색상/알파 파라미터 조정만으로 제어 가능. cubic_glow가 이미 같은 방식이므로 구조적 일관성도 확보됨.
