> 분석 대상: `docs/reference/physarum-real/01~13.png` + `macro-closeup/01.png`
> 분석 목적: "구름" 같은 현재 정맥을 "선/촉수" 형태로 개선하기 위한 시각적 특성 정의

---

## 1. 정맥의 시각적 특성 (레퍼런스 관찰)

### 1.1 두께

| 단계 | 주정맥 두께 (본체 직경 대비) | 모세정맥 두께 |
|------|---------------------------|-------------|
| 초기 (01~02) | 본체 직경의 ~3~5% | 거의 안 보임 |
| 성장 (03~05) | 본체 직경의 ~2~4% | ~1% 미만 |
| 성숙 (06~09) | 본체 직경의 ~2~3% | ~0.5~1% |
| 후기 (10~13) | 절대 폭 유지, 본체 소실로 상대적으로 두꺼워 보임 | 거의 소실 |

**핵심**: 정맥은 매우 **가느다란 선(line)** 이다. 본체 대비 극도로 좁다. 1500px 맵 기준 주정맥 폭은 대략 **2~5px** 수준이어야 한다.

### 1.2 경계 선명도

- **날카롭다.** 정맥 경계는 부드러운 그라데이션이 아니라 **뚜렷한 엣지**를 가진다.
- 주정맥: 1~2px 내에서 밝기가 급격히 전환. 본체 배경 → 밝은 정맥 → 본체 배경.
- 접사 사진(macro-closeup/01): 정맥은 3D 튜브처럼 융기. 가장자리가 칼로 자른 듯 선명.
- 현미경 스케일에서도 정맥 경계는 **diffuse glow 없이** 깔끔하게 끊긴다.
- 비유: 나뭇잎의 잎맥(leaf vein)과 동일한 선명도.

### 1.3 밝기 대비

- 정맥은 본체 대비 **확실히 밝다** (2~4배 밝기 차이).
- dark-field 촬영 기준:
  - 본체: 어두운 올리브그린 (RGB ~40~60, 60~80, 30~40)
  - 주정맥: 밝은 연녹~연노랑 (RGB ~140~180, 180~220, 80~120)
  - 핵/먹이원: 순백~밝은 노랑 (RGB ~240+)
- **밝기 서열**: 배경(검정) < 본체(올리브) << 정맥(밝은 연녹) < 핵/먹이(흰색/노랑)
- 정맥이 본체 "위에" 떠 있는 느낌의 핵심은 이 밝기 차이.

### 1.4 분포 패턴

- **방사형(radial)**: 핵에서 가장자리를 향해 방사상으로 뻗어나감.
- **위계적(hierarchical)**:
  - 핵 근처: 두꺼운 주정맥 소수 (3~6개)
  - 중간: 분기(branching) → 점점 가늘어짐
  - 가장자리: 미세한 모세정맥 또는 소실
- **먹이원 연결**: 먹이(밝은 점)와 핵 사이를 직접 연결하는 굵은 수송 정맥이 두드러짐.
- **본체 가장자리**: 정맥이 가장자리까지 뻗어 "촉수" 느낌을 줌. 성숙기 이후 본체 막이 후퇴하면서 정맥만 돌출.
- 정맥 사이 공간은 비교적 균일한 본체(또는 투명).

### 1.5 정맥과 본체의 레이어 관계

- **정맥은 본체 "속"에 있지만 "위에 떠 보인다".**
- 물리적으로는 본체 원형질 내부의 농축 수송 채널이지만, dark-field에서 정맥이 훨씬 밝아 시각적으로 본체 위에 겹친 별도 레이어로 인식됨.
- 접사(macro-closeup/01): 정맥은 본체 표면에서 **물리적으로 솟아** 있음 (3D 튜브 형태). 주변 본체보다 두껍고 밝은 노랑.
- 렌더링 관점: 정맥은 본체 위에 **additive/screen blend**되어야 자연스러움. 본체 알파에 묻히면 안 됨.

### 1.6 형태적 특징 — "촉수" 느낌의 핵심

1. **극도로 높은 종횡비(aspect ratio)**: 정맥 길이 >> 정맥 폭. 선(line)이지 면(area)이 아님.
2. **날카로운 경계**: 정맥 가장자리가 blur/glow 없이 뚜렷.
3. **분기(branching)**: Y자 분기가 반복되며, 분기할수록 가늘어짐.
4. **본체 돌출**: 성숙기 이후 본체가 후퇴하면 정맥만 배경 위에 노출 → "촉수" 느낌 극대화.
5. **비균일 간격**: 정맥은 균일하게 분포하지 않음. 수송 수요에 따라 밀집/희소 영역 존재.

## 2. 현재 구현과의 갭 분석

### 2.1 현재 셰이더 (`veins.frag.glsl`) 방식

현재 정맥 검출 로직:
```
3x3 블러 → 능선(ridge) 검출 → 상대적 ridge 비율 → smoothstep 필터링
```

**문제점:**

| 항목 | 레퍼런스 | 현재 구현 | 갭 |
|------|----------|----------|-----|
| 정맥 폭 | 2~5px의 가느다란 선 | STEP=8, 3x3 블러 → **넓은 영역**이 ridge로 감지 | 정맥이 두꺼운 "구름"으로 보임 |
| 경계 선명도 | 칼로 자른 듯 날카로움 | smoothstep(0.2, 0.5) + 블러 → **부드러운 그라데이션** | 경계가 흐릿 |
| 밝기 대비 | 본체 대비 2~4배 밝음 | `densityT * ridgeStrength * layerAlpha` → 알파 곱셈으로 **약해짐** | 대비 부족 |
| 형태 | 선형(line), 분기 구조 | 등방성(isotropic) ridge → **방향 무관한 영역 감지** | 선이 아닌 영역(blob)으로 보임 |
| 레이어 | 본체 위에 떠 보임 | 본체와 같은 레벨에서 알파 블렌딩 | 본체에 묻힘 |

### 2.2 근본 원인

1. **Ridge 검출 스케일이 너무 큼**: STEP=8로 3x3 블러 (24px 범위) + farTexel (32px 범위) → 실제 정맥(2~5px)보다 훨씬 넓은 영역을 하나의 ridge로 뭉침.
2. **등방성 검출**: 상하좌우 4방향 평균과 비교 → 방향 정보 없음 → 선형 구조를 감지하지 못하고 "볼록한 영역" 전체를 잡음.
3. **알파 감쇠 체인이 너무 긺**: `densityT * ridgeStrength * layerAlpha * layerPulse` → 4개 팩터 곱 → 대부분의 픽셀이 매우 낮은 알파 → 희미한 구름.
4. **블러가 선명도를 파괴**: 3x3 블러가 입력 자체를 부드럽게 만들어, 이후 ridge 검출이 날카로운 정맥을 잡지 못함.

### 2.3 Config 파라미터 갭

| 파라미터 | 현재 값 | 문제 |
|---------|--------|------|
| `STEP: 8` | 8px 간격 → 24px 블러 범위 | 너무 넓음. 정맥 폭(2~5px)보다 큼 |
| `RIDGE_SCALE: 3.0` | 상대적 ridge에 3배 스케일 | smoothstep(0.2, 0.5)과 조합하면 너무 많은 영역이 통과 |
| `MINOR_ALPHA: 0.15` | 모세정맥 최대 알파 15% | 너무 약해서 보이지 않음 (레퍼런스에서는 모세정맥도 보임) |
| `MAJOR_THRESHOLD: 40` | 트레일 40 이상 = 주정맥 | 본체 중심 트레일이 ~130이면 대부분이 주정맥으로 분류됨 |
| `MIN: 25` | 트레일 25 미만 무시 | 본체 가장자리의 가느다란 정맥을 놓칠 수 있음 |

## 3. 개선 방향 제안

### 3.1 핵심 원칙

> 정맥은 **선(line)**이다. 영역(area)이 아니다.

현재의 "등방성 ridge 검출"로는 선 형태를 만들 수 없다. 근본적 접근 변경 필요:

### 3.2 접근 옵션

**옵션 A: 비등방성(anisotropic) 필터링**
- 라플라시안 대신 헤시안(Hessian) 행렬의 고유값 분석
- 하나의 고유값만 큰 경우 = 선(ridge), 둘 다 큰 경우 = 점(blob)
- 선의 방향도 알 수 있어 정확한 정맥 폭 제어 가능
- 복잡도: 중간 (2x2 헤시안 + 고유값 = 추가 texture fetch 4~8개)

**옵션 B: 멀티스케일 + 임계값 강화**
- 블러 반경을 줄이고 (STEP=2~3), ridge 임계값을 높여서 날카로운 피크만 통과
- smoothstep 범위를 좁게 (0.4, 0.6) → 약한 ridge 급격히 제거
- 구현 간단하지만 근본적으로 "선 vs 면" 구분 불가

**옵션 C: 트레일맵 직접 임계값 (non-ridge 방식)**
- ridge 검출 대신, 트레일 값 자체의 높은 임계값으로 정맥 추출
- 예: `trailValue > 본체평균 * 1.5` 인 픽셀만 정맥으로 표시
- 가장 단순하지만, 고밀도 본체 중심이 통째로 정맥이 될 위험

### 3.3 권장: 옵션 A (헤시안 Ridge)

레퍼런스의 "촉수/잎맥" 느낌을 가장 정확히 재현할 수 있는 방법.
핵심 변경점:
1. 3x3 블러 제거 또는 최소화 (1px 가우시안만)
2. 헤시안 고유값으로 선형 ridge만 추출
3. ridge 폭(정맥 두께)을 고유값 비율로 제어
4. 알파를 ridge 강도에 직결 (중간 곱셈 체인 축소)
5. 본체 위에 additive blend로 밝기 차이 보장

## 4. 정맥의 시각적 스펙 (구현 목표)

레퍼런스 기반으로 정의한 "정답" 정맥의 시각적 사양:

| 속성 | 목표값 |
|------|--------|
| 주정맥 폭 | 2~4px (1500px 맵 기준) |
| 모세정맥 폭 | 1~2px |
| 경계 전환 거리 | 1px 이내 (sharp edge) |
| 밝기 (본체 대비) | 2~4배 밝음 |
| 블렌딩 | additive 또는 screen (본체 위에 떠 보여야 함) |
| 알파 범위 | 주정맥 0.7~0.9, 모세정맥 0.3~0.5 |
| 분포 | 핵에서 방사상, Y분기, 먹이원 연결 강조 |
| 색상 | 밝은 연노랑~연녹 (본체의 올리브보다 확실히 밝고 따뜻함) |

## 5. shader-analyst 질문에 대한 답변

> shader-analyst 분석 참조: `docs/research/shader-analyst-result.md`

### Q1. 확산으로 9px 퍼진 트레일에서 Hessian이 "선"을 잡아낼 수 있을까?

**결론: 조건부로 가능하지만, 레퍼런스 품질의 "선"은 불가능.**

레퍼런스 관찰에서 정맥 폭은 2~5px이다. 확산 4패스가 ~9px 반경의 가우시안 블러를 적용하면, 원래 2~5px 폭의 수송 채널이 ~20~25px 폭으로 퍼진다. Hessian은 이 퍼진 프로파일에서 "가장 곡률이 큰 중심선"을 추출할 수 있으므로, **중심선 1~2px은 잡아낼 수 있다**.

그러나 문제는:
- 확산으로 인접한 수송 채널들이 겹쳐 하나의 넓은 "구릉"으로 합쳐지는 경우, Hessian이 분리된 선을 구분하지 못한다.
- 모세정맥(원래 1~2px)은 확산 후 완전히 사라져, Hessian이 검출할 정보 자체가 없다.
- 레퍼런스의 **날카로운 경계**(1px 전환)는 9px 블러된 입력에서 절대 복원 불가.

**비유**: 안경 없이 찍은 흐린 사진에서 포토샵 sharpen을 돌리면 윤곽은 드러나지만, 원본의 선명함에는 도달하지 못하는 것과 같다.

따라서 **Hessian 단독으로는 부족하고, 미확산 트레일맵(방법 E)과 결합해야** 레퍼런스 수준의 정맥이 가능하다.

### Q2. "선"이 아니더라도, 본체 위에 additive로 밝은 색을 얹으면 시각적으로 "촉수" 느낌이 나올까?

**결론: "촉수" 느낌의 50~60%는 달성 가능하다.**

레퍼런스를 다시 관찰하면, "촉수" 느낌의 요소별 가중치:

| 요소 | 기여도 | additive만으로 달성? |
|------|--------|---------------------|
| 본체 대비 확실히 밝음 | 30% | **YES** — additive blend = 무조건 밝아짐 |
| 가느다란 선형 형태 | 40% | **NO** — 입력이 퍼져있으면 넓은 글로우가 됨 |
| 날카로운 경계 | 20% | **NO** — 블러된 입력 → 부드러운 그라데이션 글로우 |
| 본체 가장자리 돌출 | 10% | **PARTIAL** — 가장자리에서 배경 위 additive는 효과적 |

additive blend를 현재의 SRC_ALPHA blend 대신 적용하면:
- **장점**: 정맥이 본체 위에서 확실히 밝아지므로 "위에 떠 있는" 느낌은 즉시 개선
- **장점**: 본체 가장자리~배경 경계에서 정맥이 배경 위에 직접 빛나므로 "촉수 돌출" 느낌
- **한계**: 넓은 영역이 밝아지면 "발광하는 구름"이 될 위험 — "촉수"가 아니라 "오로라"

**핵심 관찰**: 레퍼런스에서 정맥이 "촉수"로 보이는 가장 큰 이유는 밝기가 아니라 **형태(가느다란 선)**이다. 밝기만으로는 "빛나는 구름"에서 "빛나는 촉수"로의 전환이 일어나지 않는다.

### Q3. 현실적 타협안

레퍼런스 관찰 + shader-analyst의 기술 분석을 종합한 **단계적 접근**:

#### Phase 1: 즉시 개선 (블렌딩 + 파라미터만, 셰이더 로직 변경 없음)

1. **블렌딩을 additive로 변경** (`gl.blendFunc(SRC_ALPHA, ONE)`)
   - 정맥이 본체 위에서 밝아지는 효과 즉시 달성
   - "위에 떠 있는" 느낌 +30%
2. **알파 곱셈 체인 단순화**: `ridgeStrength * layerAlpha * layerPulse` (densityT 제거)
   - 넓은 영역의 균일한 밝기 방지
3. **강한 임계값**: smoothstep(0.4, 0.6)으로 좁혀서 약한 ridge 급격히 제거
   - "구름"의 가장자리를 잘라내어 상대적으로 좁게

기대 효과: 현재의 "구름"에서 → "밝은 구름 + 약간 선형적인 구조"로 개선. 50% 수준.

#### Phase 2: 핵심 개선 (미확산 트레일맵 = 방법 E)

shader-analyst의 방법 E가 **가장 현실적이고 효과적**이다.

이유 (레퍼런스 관점):
- 레퍼런스 정맥은 **원형질 흐름의 농축된 채널**이다. 확산은 페로몬 신호의 전파이지, 원형질 자체의 물리적 분포가 아니다.
- 따라서 "에이전트가 실제로 모여있는 곳" = 미확산 deposit 맵이 정맥의 물리적 실체에 가장 가깝다.
- 미확산 맵에서는 수송 채널이 **원래 폭(2~5px)**을 유지하므로, 단순한 ridge 검출로도 선형 구조를 잡아낼 수 있다.

구현:
- TrailMapGPU에서 확산 전 deposit 결과를 별도 FBO에 보관 (ping-pong 중 하나 재활용 가능성 검토)
- 정맥 셰이더가 미확산 텍스처를 uniform으로 받아 ridge 검출

#### Phase 3: 정밀 개선 (Hessian, 미확산 맵 입력)

미확산 맵이 확보되면, Hessian ridge 검출은 매우 효과적이다:
- 입력이 날카로우므로 2~5px 폭의 선을 정확히 잡음
- 고유값 비율로 선형 vs 둥근 구조 구분 가능
- 모세정맥도 검출 가능

#### 종합 권장 경로

```
Phase 1 (즉시): additive blend + 파라미터 조정 → 50% 개선
Phase 2 (핵심): 미확산 트레일맵 분리 → 80% 개선
Phase 3 (정밀): Hessian + 미확산 맵 → 95% 개선
```

**Phase 2가 가장 비용 대비 효과가 크다.** Phase 1은 근본 해결이 아니지만 즉시 시각적 개선을 보여줄 수 있고, Phase 2와 3는 순차적으로 추가하면 된다.
