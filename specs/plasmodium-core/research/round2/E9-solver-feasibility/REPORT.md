# E9 — solver feasibility: E1 정맥 나무는 GPU용 근사 압력 풀이에서도 유지되는가 (REPORT)

상태: **완료** (판정: partial — 15절). 실행 표 전체는 summary_all.txt, 대표 이미지는 montage/m1~m4.

## 0. 가설
E1(전진면 싱크 + 전역 압력 + 간선 전도도 초선형 강화)의 정맥 나무는, 희소 직접 풀이를
프레임당 풀스크린 패스 약 60회 이내의 GPU용 근사 풀이로 바꿔도 유지된다:
(a) 웜스타트 감쇠 Jacobi / heavy-ball(Chebyshev류) k회, (b) 가변 계수 기하 멀티그리드 V-사이클,
(c) 1/2~1/4 해상도 압력. 정규 텍스처 격자, 간선 전도도 4채널(E, N, NE, NW).

## 1. 모델 (E1 e1.py 의 grow 모드를 그대로 옮김; e1_copy.py = 원본 사본, e9.py = 이 실험 코드)
- 격자 N×N, 노드 = 셀, 간선 4채널: d ∈ {E(1,0), N(0,1), NE(1,1), NW/SE(1,−1)}, 길이 L = 1 또는 √2.
- 몸 wet(t): 미리 정한 속도 v 로 자라는 울퉁불퉁한 원반. T(x) = (|x−c| − R_init + front_rough·η(x))/v, η = 가우시안(σ=2셀) 평활 백색잡음(표준편차 1). wet = T ≤ t.
- 소스/싱크: 전진면 셀(마른 이웃이 있는 젖은 셀)마다 S = −j0, 중심 반지름 2셀 원판에 합이 0 이 되도록 균등 소스.
- 압력: Σ_e w_e (p_i − p_j) = S_i,  w_e = G_e (C_e + r)/L_e.  G_e = exp(σ_e·N(0,1)) 정적 로그정규 간선 잡음(σ_e = 0.5), r = 1e-3 배경.
- 유량 Q_e = w_e (p_i − p_j).  적응: C_e ← C_e + dt·rate·((|Q_e|/Q0)^γ − C_e), γ = 1.5.  새 간선 C = D0(1 + 0.3·U(−1,1)).
- 초기 조건: 반지름 6셀 원반, 모든 간선 C = D0(±30% 백색잡음). 정맥 경로를 심지 않는다.
- 기준 스케줄(E1 f_ 계열): v = 1 셀/시간, dt = 0.2 → 스텝당 전진 0.2셀, rate·dt = 0.2/스텝. N=256 → 507 스텝, 최종 반지름 107셀.

## 2. 근사 풀이 (전부 9점 스텐실 연산만. 희소 직접 풀이는 기준선과 오차 측정에만 사용)
A p = S, A = 그래프 라플라시안(위 w_e), D = diag(A).
- **jac(k, ω)**: p ← p + ω D⁻¹(S − A p), 스텝당 k회, 이전 스텝 p 에서 시작(웜스타트). GPU: k 패스.
- **hb(k, ω, β)** heavy-ball(2차 Richardson = 감쇠 파동): p⁺ = p + ω D⁻¹(S − A p) + β(p − p⁻). 운동량도 스텝 사이에 유지. GPU: k 패스(핑퐁 텍스처 2장이 곧 p, p⁻).
- **gs4(k)**: 4색 Gauss–Seidel (sq8 은 대각 이웃 때문에 red-black 2색이 아니라 4색 필요). GPU: 스윕당 4 패스.
- **mg(ncyc, ν1, ν2, ω)**: 셀 중심 2× 조대화 기하 멀티그리드 V-사이클. 제한 = 2×2 합, 보간 = nearest(2×2 복제),
  조대 연산자 = ½·PᵀAP (집합체 사이를 건너는 미세 간선 가중치의 합의 절반; sq8 4채널 구조가 그대로 유지됨:
  E_c = ½(E 2개 + 건너는 대각 2개), NE_c = ½(모서리 대각 1개)). 평활 = 감쇠 Jacobi. 최조 격자에서 Jacobi n_c 회.
  GPU 패스: 레벨당 ν1 + 1(잔차+제한) + 1(보간+가산) + ν2, 조대 연산자 재구성 레벨당 1.
- **pcg(tol)**: MG V(2,2) 전처리 CG. 512² 기준해(직접 풀이가 5분을 넘음)와 "오차를 임의로 줄일 수 있는 상한" 용.
  GPU 에서는 내적(밉맵 축소) 때문에 비싸다 — 후보가 아니라 기준.
- **vpipe(k, a, b)** (전역 풀이 없는 대안, 6번 과제): 간선 유량이 상태. Q_e ← Q_e + a(w_e Δp − Q_e); p_i ← p_i + b(S_i − div Q)_i / D_i. 적응은 Q 로.
- 옵션: solve_every=m (압력은 m 스텝마다만 갱신), adapt_every, 조대 격자 압력(lvl0 평활 수를 줄이거나 0), r 하한, 대비 상한 C_cap, 전도도 약한 확산 Dm, float32.

**중요한 부정적 결과**: E1 스케줄(적응 시간상수 = 5 스텝)에서는 국소 반복 풀이가 "형태가 조금 달라지는" 정도가 아니라 **전도도가 폭주한다**. Jacobi 는 스텝당 200패스로도 안 된다.
기전(분석): 강화 dC/dt = rate((CΔp)^γ − C) 는 Δp 가 고정이면 γ>1 에서 폭주하는 양의 되먹임이다. 정확한 풀이에서는 C 가 커지면 Δp 가 즉시 1/C 로 줄어(유량 보존) 안정되지만,
압력이 늦게 따라오면(정맥을 따라 L² 패스가 걸리는 확산) 그 사이 Q=CΔp 가 총전류보다 커진다. 폭주 반지름이 k 와 함께 27→57→84→98 로 커지는 것이 이 그림과 맞는다.
(확인, 배치 I) 위 표의 jac k=200(@459)과 hb β=0.90 k=20(@467)은 섬 인공물 시점(스텝 448, 8절) 이후라 islands='drop' 으로 다시 돌렸다: jac k=200 은 같은 스텝 459(R=98)에서 폭주(평균 유량 오차 267 — 섬과 무관한 진짜 실패), hb β=0.90 k=20 은 R=105.6 에서 폭주(평균 오차 2.0), **hb β=0.90 k=60 은 완주·통과**(유량 오차 0.074/0.084, bp 172, 정맥 수 5/10/18/39, IoU 0.45).
→ 관건은 "스텝당 패스 수"가 아니라 **적응 시간상수당 패스 수 n_adapt = k/(rate·dt)** 와 몸 크기의 관계다. 다음 배치(C)는 dt 를 줄여(= 게임처럼 프레임당 적응을 작게) n_adapt 를 스윕한다.

  본체와 떨어진 3~7셀짜리 젖은 섬을 만든다. 섬은 전진면 싱크만 있고 소스가 없어 연립방정식이 그 성분에서 비양립이다. 직접 풀이는 영향이 없지만(E1 은 1e-10 정칙화),
  반복 풀이는 섬의 압력이 스윕마다 표류하다가 섬이 본체에 붙는 순간 거대한 Δp 로 강화를 폭주시킨다. **이것은 운동학적 전진면 설정의 인공물**이다(실제 게임에서는 S 가 질량 보존 동역학에서 나오므로 성분별로 양립).
  → e9.py 에 islands='drop'(소스와 연결된 성분만 젖은 것으로 침) 추가, 이후 배치는 전부 이 설정. **GPU 구현 교훈: 성분별 소스 합이 0 이 아니면 압력이 표류한다 — S 는 반드시 보존형으로 만들 것.**
- R<95 에서의 폭주(위 표의 굵은 "폭주")는 섬과 무관한 진짜 지연 불안정이다(시드 1 은 스텝 448 전에는 섬이 없음).

오차 허용 한계(5번 과제): 형태 통계가 유지된 실행의 평균 순간 유량 오차는 0.05~0.35, 실패한 실행은 대부분 0.4 이상(Jacobi 0.5, MG1.0 0.53, 512² 1사이클 0.36→0.47). 한계를 넘으면 "형태가 서서히 나빠지는" 것이 아니라 **전도도 폭주**로 간다.
경계 근처(0.25~0.35)에서는 통과해도 줄기에 지그재그 인공물과 Cmax 과도 초과(기준의 4~6배)가 보인다(montage/m3_variants.png 의 f_mg15_c1e4_ae4_dt05, f_vp_a10_k30).
"적응이 느리면 웜스타트가 따라간다"는 지지: MG 1사이클/스텝의 유량 오차는 256² 에서 rate·dt 0.2 → 0.05 로 0.21 → 0.08, 512² 에서 폭주 → 0.06. Jacobi 60패스도 rate·dt=0.02 면 유지.

### 750² 외삽 (측정하지 않음 — 두 크기에서의 외삽)
- MG: 적응 시간상수당 필요한 V(2,2) 사이클 수가 R=107 에서 1.25(실패)~5(유지), R=215 에서 5(실패)~10(유지). 필요량 ∝ R 이면 R=315(750² 의 0.42배)에서 약 15, ∝ R² 이면 약 40.
  프레임당 1사이클이면 적응 시간상수가 15~40프레임 이상(rate·dt ≤ 0.025~0.07/프레임)이어야 한다. 게임에서 정맥 적응을 0.5초(30프레임)보다 느리게 잡으면 들어온다.
  E1 의 조건 v/(rate·R) ≲ 0.07 과 함께 쓰면: 전진 0.2셀/프레임, R=300 → rate·dt ≥ 0.0095/프레임. 즉 **rate·dt 를 0.01~0.05/프레임** 범위에 두면 두 조건을 모두 만족(여유 1~4배).
- heavy-ball: E1 스케줄 60패스가 R=215 에서 이미 경계(시드 1개 폭주). 750² 에서는 rate·dt ≤ 0.05 + Ccap 을 전제로만 후보. β 를 몸 크기에 맞춰야 할 가능성(β=0.99 는 작은 몸에서 폭주, 0.9 는 큰 몸에서 부족) — 미검증.
- Jacobi: 256² 에서 적응 시간상수당 3,000패스(60패스 × 50스텝)가 유지, 1,200 은 실패. 정적 수렴이 R² 에 비례하므로 750² 에서는 약 2.6만 패스/시간상수 → 60패스/프레임이면 시간상수 ≥ 7초. 512² 이상은 시험하지 않았다.

## 14. GPU 실현성
- **전역 정보는 필요하지만 "직접 풀이"는 필요 없다.** 프래그먼트 셰이더 패스만으로 된다. 단 스텝당 예산이 부족하면 폭주하므로 아래 조건을 지켜야 한다.
- 텍스처: 간선 전도도 C(E,N,NE,SE) RGBA32F 1장, 정적 간선 잡음 G RGBA 1장, p 핑퐁 R32F 2장, (MG) 레벨별 W(RGBA)·p·rhs. float32 로 충분(256²·512² 에서 확인, 512² 는 Ccap 과 함께).
- **권장 A — 멀티그리드**: 768² 로 잡으면 8레벨(768→6). V(2,2) 1사이클 = 레벨당 (평활 2 + 잔차·제한 1 + 보간·가산 1 + 평활 2) × 7 + 최조 격자 Jacobi 20 = **드로콜 62, 미세 패스 8.0회 분량**. 조대 연산자 재구성 드로콜 7(0.33 분량).
  프레임당 합계 드로콜 약 69 + 모델 패스 2(싱크/소스, 유량+적응) ≈ **풀스크린 환산 10패스, 드로콜 71**. 적응을 4프레임에 한 번 하고 그때만 V-사이클을 돌리면 프레임 평균 드로콜 약 18, 2.3 분량(256² 에서 시드 2개 확인, 줄기 인공물 약간).
- **권장 B — heavy-ball / virtual pipe**: 셰이더 1개, 9탭, p 핑퐁. 프레임당 20~60패스 = 드로콜 20~60, 풀스크린 20~60회 분량(몸 경계 상자 scissor 로 면적만큼 줄어듦). 구현은 훨씬 단순하지만 512² 에서 시드 1개가 폭주했다.
- 몸 경계 상자만 풀기: 수치적으로는 같은 연산(몸 밖은 간선이 없어 p=0)이라 따로 시험하지 않았다. 채우기 비용만 줄고 드로콜 수는 같다. 상자를 알려면 CPU 가 몸 범위를 알아야 한다.
- 전도도 적응을 k프레임마다: 유효(위). 반대로 **압력은 가끔, 적응은 매 프레임**은 불안정했다.
- 압력을 조대 격자에서 풀기(가설 c): **불가**. 1/2·1/4 해상도 압력을 올려 쓰면 R=8~12 에서 폭주하거나 망이 조각난다(연결 0.19). 미세 레벨 평활을 0+1 로 줄여도 R=65 에서 폭주. 정맥이 1간선 폭이라 미세 격자의 압력이 꼭 필요하다.
  (정맥 모델 전체를 저해상도 격자에서 돌리고 렌더만 올리는 것은 별개이며, 256²/512² 결과가 그대로 그 경우다.)

## 15. 판정: **partial**
- 지지되는 부분: (b) 멀티그리드 V-사이클은 256²·512² 에서 시드 2개씩 나무를 유지한다(프레임당 풀스크린 8~16회 분량). (a) 중 heavy-ball 은 256² 에서 유지, 512² 는 시드 1개만.
- 지지되지 않는 부분: (a) 순수 웜스타트 Jacobi 는 E1 스케줄에서 200패스로도 폭주(느린 적응에서만 유지). 4색 GS 도 폭주. (c) 저해상도 압력은 전부 실패.
- 가설에 없던 조건 3개가 필요했다: (1) MG 조대 연산자 과보정을 2 가 아니라 1.5 로(문헌 노트 구성은 발산), (2) 적응 속도를 풀이 속도에 맞추거나 전도도 상한 Ccap 을 둘 것, (3) 소스/싱크가 연결 성분별로 합 0 일 것.

## 16. 권장 풀이 구성 (숫자)
1. 격자 768²(또는 512²), 간선 4채널, w = G·(C + r)/L, r = 1e-3~0.03 (r=0.03 은 유량 오차를 0.21→0.12 로 줄임), 간선 잡음 σ=0.5.
2. 압력: 기하 멀티그리드 V(2,2), 감쇠 Jacobi ω=0.8, 제한 = 2×2 합, 보간 = nearest, **조대 연산자 = PᵀAP/1.5**(E_c = (E 2개 + 건너는 대각 2개)/1.5, NE_c = 모서리 대각/1.5), 최조 격자(4~6²) Jacobi 20회, 프레임당 1사이클 웜스타트.
3. 적응: C ← C + a((|Q|/Q0)^1.5 − C), **a = rate·dt ≤ 0.05/프레임**, C ≤ Ccap (256² 에서 1000, 512² 에서 3000 을 썼다. 줄기 굵기를 깎으므로 굵기 위계를 보고 정할 것).
4. 예산이 빠듯하면 "4프레임마다 V-사이클 1회 + 그 프레임에만 적응(4프레임치)".
5. 대안: heavy-ball p⁺ = p + 0.886·D⁻¹(S − Ap) + 0.97(p − p⁻), 프레임당 20~60패스, Ccap 필수.

## 17. 실패한 시도·부정적 결과 (모음)

- V(1,1): R=102 폭주. MG 전처리 CG + 과보정 1.5: 전처리가 부정부호가 되어 200회 반복에서 멈춤(과보정 1.0 은 정상, 평균 36.7회 — GPU 후보 아님).

## 18. 한계
- 750² 는 돌리지 않았다. 외삽은 두 크기(256², 512²)뿐이고 필요량의 R 의존 지수를 정하지 못했다.
- 512² 는 같은 시드 직접 풀이 기준선이 없다(5분 제한). 순간 유량 오차와 E1 의 스케일 불변 통계로만 판단했다.
- 몸은 E1 처럼 미리 정한 속도로 자라는 원반이다. 이동하는 몸, 맥동(AC) 소스, 요동 싱크, 고리는 시험하지 않았다. 문헌 노트는 Jacobi 가 AC 성분을 못 따라간다고 했고 heavy-ball 의 AC 추적은 재지 않았다.
- 공통 채점은 E1 과 같은 렌더 규칙(지름 0.7·C^¼ 셀 관, 256² 4배·512² 2배 래스터)에 의존한다. 512² 의 분기점 수는 256² 과 직접 비교할 수 없다.
- 근사 풀이는 같은 시드에서도 직접 풀이와 다른 정맥을 만든다(IoU 0.3~0.46). 보존되는 것은 통계다.
- Kirchhoff L1 잔차는 유량 L2 오차가 작아도 0.1~0.9 로 크다(고전도 노드의 국소 잔차). 이 유량으로 두께장을 옮길 때의 영향은 보지 않았다.
- Ccap 값·heavy-ball 계수는 각각 1~2개 값만 시험했다. 시드는 2개까지.
- numpy/numba float64 스텐실로 GPU 패스를 흉내 냈다(float32 는 3건). 실제 WebGL2 드로콜 비용은 측정하지 않았다.
- 계산 시간: 실행 84건의 실행 시간 합 44.3분(프로세스 2개 병렬, 벽시계 약 30분)으로 예산 상한(30~40분)을 조금 넘겼다.
