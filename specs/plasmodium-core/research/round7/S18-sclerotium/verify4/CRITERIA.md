# verify4 — S18 후보 독립 검증: 미리 정한 기준

이 문서는 **실행 전에** 쓰고 sha256 을 `criteria_sha256.txt` 에 적어 커밋한다. 실행 뒤에 바꾸는 것은 모두 `CRITERIA_CHANGES.md` 에 원래 판정과 함께 남긴다.

- 후보(꼬리표 `v4w`): `keep_conn=4 fis_min=0.10 ret_h=100 ret_glob=1 sup_age=100 sup_cap=2 sup_h=0.6 sup_fed=50 ret_fed=50 hang_age=4 sup_min=0.05 neg_fill_global=1 sup_size=2 hang_C=20 scl_f=0.02 scl_H=3 scl_age=5 scl_C=20 scl_disc=1 scl_thin=0 sup_scent=2 scl_dlim=1 scl_bk=2 scl_shmin=1e-9`
- 대조(꼬리표 `v4c`): 덧붙인 설정 없음.
- 읽은 코드: `model/ref_model.py`, `export_ref.py`, `mgt.py`, `graphm.py` 만. 측정은 `verify4/scripts/measure.py`, 판정은 `verify4/scripts/judge.py` (둘 다 내가 쓴 것).

## 0. 코드를 읽고 확인한 것 (측정의 바탕)

- `vs_tNNNN.npz` 는 20 시간 단위마다, 그 스텝의 마름·젖음이 끝난 뒤의 상태다. `h`, `wet` 은 그 순간, `hmean` 은 직전 한 주기(4 시간 단위) 동안 줄곧 젖어 있던 칸의 평균 두께(아니면 0), `Qgross[k]` 는 직전 20 시간 단위 동안 간선 흐름 `|Q|` 의 평균이다(간선 k 는 칸 (y,x) 에서 `DIRS[k]` 쪽 이웃으로).
- `slime`(점액)은 `vs` 에 없다. 칸이 마를 때 1 이 되고 사라지지 않는다. 그래서 나는 "지금까지 스냅숏에서 한 번이라도 젖었던 칸 + 처음 원반"의 합집합 U 로 점액을 어림한다. 끝(T)에서 실제 `slime.npy` 와 비교해 얼마나 잡았는지 보고한다.
- `metrics.json`: `mass_err_max` = 스텝마다 `|Σh − V0 − Vinj + V_crumb| / V0` 의 최대(버린 부피를 빼고 본 수치 오차). `V_crumb` = 외톨이 셀 마름(crumb_dry)으로 버린 부피. `neg_end_cellsteps` = 스텝 끝에 두께가 음수인 젖은 칸-스텝 수, `h_min_end_of_step` = 그 최소값. `stop` 이 빈 문자열이면 끝까지 돈 것. `t_touch[k]` = 먹이(또는 유인원) k 의 원반에 처음 젖은 칸이 생긴 시각.
- `long` 은 `mig` 와 T 만 다르다(`export_ref.py` 의 SCN). 그래서 long 의 t ≤ 400 은 같은 시드의 mig 와 같은 실행이다. long 에도 유인원(27°, 70칸, 세기 0.5) 하나가 있다(먹을 수는 없다).
- 후보의 균핵 상태(`scl`)는 모델 안의 점액 비율로 켜지며, 처음 켜진 시각만 `metrics.json` 의 `t_scl` 에 남는다.

## 1. 공통 측정 정의 (measure.py)

모든 연결은 **토러스 위 8-이웃**이다. 두께 판별에는 `heff` = `hmean`(>0 이면) 아니면 `h` 를 쓴다(맥동 ±10% 로 문턱을 넘나드는 것을 막으려고). 부피는 늘 `h` 의 합이다. V = 그 스냅숏의 젖은 칸 전체 부피.

| 이름 | 정의 |
|---|---|
| 몸(body) | 젖은 칸의 8-연결 조각 |
| 부스러기 | 부피 < 0.05 V 인 몸 |
| 큰 몸 | 부피 ≥ 0.05 V 인 몸 |
| 굵은 덩이(lump) | `wet & heff ≥ 0.5` 를 반지름 2 원반(5×5 에서 네 귀퉁이 뺀 21칸)으로 열기(opening) 한 뒤의 8-연결 조각 중 부피 ≥ 0.05 V. (폭 4칸 이하의 실·줄기는 덩이가 아니다) |
| 여러 덩이 몸 | 덩이가 둘 이상 든 몸 |
| 아령 | 여러 덩이 몸에서 어떤 두 덩이 A, B 를 몸 안에서 가르는 데 지워야 할 칸 수의 최소(최소 정점 절단, 최대 흐름으로 계산)가 3 이하 |
| 덩이 수 n_mass | 큰 몸마다 max(1, 그 몸의 덩이 수) 를 더한 것 (덩이 없는 큰 몸도 한 덩어리로 센다) |
| 가는 칸 | 젖은 칸 중 젖은 3×3 정사각형 안에 하나도 들지 못하는 칸 (폭 2칸 이하인 곳) |
| 얇은 막 | `wet & heff < 0.3` 을 3×3 정사각형으로 열기 한 뒤 남는 칸 (두께 0.3 미만이 넓게 펼쳐진 곳), 칸 수 |
| 칸 흐름 q | 0.5 × (칸에 닿는 8 간선의 `Qgross` 합) |
| 흐름 없음 | q < 0.05 × (그 스냅숏 젖은 칸 q 의 90 백분위) |
| 흐름 없는 죽은 실 | 가는 칸이면서 흐름 없음, 칸 수 |
| 가지 끝 | 가는 칸 덩어리(8-연결) 가 5칸 이상인 것 안에서, 젖은 이웃이 1~3 칸이고 그 이웃들이 한 무리(8-연결)인 칸들의 8-연결 무리. 하나가 끝 하나 |
| 흐름 없는 가지 끝 | 그 끝 무리 안 q 의 최대가 흐름 없음 문턱 아래 |
| 큰 몸 모양 | 부피가 가장 큰 몸의 젖은 칸으로: K = 면적 / (2π Rg²) (원반 1, 길쭉하거나 가지가 많으면 작다), lam = 2차 모멘트 작은/큰 고유값 비 (원반 1), 가는 칸 비율 |
| 새 땅 비율 fresh | 가장자리(젖은 칸에 닿은 마른 칸) 가운데 U(앞 스냅숏까지의 젖은 칸 합집합 + 처음 원반)에 들지 않는 칸의 비율 |
| 갇힘 시각 T_trap | 그 시각부터 끝까지 모든 스냅숏에서 fresh < 0.05 가 되는 가장 이른 스냅숏 시각 (없으면 갇히지 않음) |

## 2. 주장별 측정과 판정 규칙

### 공통 통계 규칙 (judge.py)
- 짝 = 같은 시나리오·같은 시드의 대조와 후보, 둘 다 끝까지 돈 것. 실행마다 창 안 스냅숏의 평균을 한 값으로 쓰고, 짝 차이 d = 후보 − 대조.
- 검정: 짝 Wilcoxon 부호 순위(0 차이 뺌), 한쪽, 유의수준 0.05.
- **"후보가 낮다" 판정**(lower_test): 짝 6 미만 → 판정 못 함. 대조 평균이 바닥값(floor) 미만이면 → 후보가 유의하게 높을 때만 틀림, 아니면 판정 못 함(대조에서도 드묾). 그 밖에: 평균 d < 0 이고 중앙값 d ≤ 0 이고 p(낮음) < 0.05 → 맞음; 평균 d ≥ 0 이거나 p(높음) < 0.05 → 틀림; 나머지 → 판정 못 함. "후보가 높다" 는 부호를 뒤집어 같은 규칙.
- **"나쁘지 않다" 판정**(noninf): d 를 "양수 = 후보가 나쁨" 쪽으로 돌린다. 효과(중앙값, 닿은 수만 평균)가 여유(margin) 이하 → 맞음; 효과 > 여유 이고 p(나쁨) < 0.05 → 틀림; 효과 > 여유 이지만 유의하지 않음 → 판정 못 함.
- 주장 하나에 하위 측정이 여럿이면: 하나라도 틀림 → 틀림, 모두 맞음 → 맞음, 나머지 → 판정 못 함.

### 주장 1. 부스러기가 없다
- 대상: 모든 시나리오의 모든 실행, 스냅숏 t ≥ 100 과 끝 상태(마지막 스냅숏 = 끝 상태).
- 1a 후보: 부스러기가 한 스냅숏에라도 있는 후보 실행이 **하나도 없으면** 맞음, 하나라도 있으면 틀림 (주장이 "만들지 않는다" 이므로 엄격하게).
- 1b 대조: t ≥ 100 에 부스러기가 있는 대조 실행이 50% 이상이면 "많이 만든다" 맞음, 아니면 틀림.
- 주장 1 = 1a 와 1b 를 합친 것. 참고로 후보의 `crumb_cells`(외톨이 셀이 마른 수; 스냅숏 사이의 부스러기 흔적), `fission_runs`(나뉨 수)를 보고한다.

### 주장 2. 옮겨 다니는 동안 덩이가 갈리지 않는다 (long)
- 창: 짝마다 100 ≤ t ≤ W, W = min(1600, 대조 T_trap, 후보 T_trap, 후보 `t_scl`). (후보가 균핵 규칙에 들어간 뒤는 옮겨 다니는 구간이 아니므로 뺀다. 이것은 후보에 불리하지 않고, 균핵 규칙이 이 주장을 대신 맞춰 주는 것을 막는다.) 창 안 스냅숏이 어느 쪽이든 10 개 미만이면 그 짝은 뺀다.
- 측정: 창 안 스냅숏 가운데 (가) 여러 덩이 몸이 있는 비율, (나) 아령이 있는 비율.
- 판정: (가), (나) 각각 lower_test(floor = 0.05). 둘 다 맞음이면 맞음.
- 민감도(판정에 안 씀): 덩이 문턱 (두께 0.5, 부피 10%), (두께 0.7, 부피 5%).

### 주장 3. 죽은 구조가 적다 (long, 주장 2 와 같은 창과 짝)
- 측정: 창 평균 (가) 얇은 막 칸 수, (나) 흐름 없는 죽은 실 칸 수, (다) 흐름 없는 가지 끝 수. long 은 먹이가 없어 두 설정의 부피가 같으므로 칸 수를 그대로 비교한다.
- 판정: 셋 각각 lower_test(floor = 1). 셋 다 맞음이면 맞음.
- 민감도: 막 문턱 0.2, 0.4; 흐름 없음 문턱 0.02, 0.10. 참고: 가는 칸 수, 가지 끝 수(흐름 무관), 면적.

### 주장 4. 갇히면 균핵이 된다 (long)
- 창: 실행마다 [T_trap + 100, 2000]. 짝의 두 실행이 모두 갇히고 각 창에 스냅숏이 3 개 이상인 짝만 쓴다.
- 상대(대조와 비교): 창 평균 n_mass 는 lower_test(바닥 없음), K 와 lam 은 "후보가 높다", 큰 몸의 가는 칸 비율은 lower_test(바닥 없음). 넷 다 맞음 → 상대 맞음. 짝이 6 미만이면 상대는 판정 못 함. (대조도 늘 한 덩어리여서 n_mass 차이가 없으면, "대조보다 덩이 수가 적다" 는 말 그대로 틀림으로 본다.)
- 절대(균핵이 되는가): 갇힌 후보 실행(창 스냅숏 3 개 이상)의 끝 상태가 n_mass = 1, 큰 몸 1 개, K ≥ 0.75, lam ≥ 0.5 이면 "균핵". 그 비율 ≥ 0.8 → 맞음, < 0.5 → 틀림, 그 사이 → 판정 못 함. 갇힌 후보 실행이 6 미만이면 판정 못 함.
- 주장 4: 절대나 상대 중 하나라도 틀림 → 틀림, 둘 다 맞음 → 맞음, 나머지 → 판정 못 함.
- 참고(판정에 안 씀): 고정 창 [1800, 2000] 에서 같은 비교. 끝에서 U 가 실제 점액을 얼마나 잡았는지.

### 주장 5. 먹이 찾기와 이주는 나빠지지 않는다
- food4·food3·asym3 (시나리오마다): (가) 닿은 먹이 수(`t_touch` 가 있는 먹이 수) — 여유: 평균 0.25 개; (나) 먹이별 닿는 시각의 평균(닿지 못한 먹이는 T 로 둠) — 여유: 대조 중앙값의 10%. 참고: 첫 닿음 시각.
- 셋을 묶어서: 닿은 수 차이(여유 평균 0.25), 닿는 시각의 상대 차이(시나리오별 대조 중앙값으로 나눔, 여유 0.10).
- mig: mig 시드 413~420 과 long 시드 401~412 의 t ≤ 400 (같은 실행) 을 합친 20 짝. (가) 유인원에 닿는 시각(400 에서 자름) — 여유: 대조 중앙값의 10%; (나) t = 200 에서 유인원 쪽으로 간 거리(질량 중심 이동을 유인원 방향에 투영, `metrics.json` 의 traj) — 여유: 대조 중앙값의 10%; (다) 가는 방향 오차 = 처음 중심에서 min(닿는 시각, 200) 의 중심으로 가는 방향과 유인원 방향 사이 각(이동이 5칸 미만이면 90°) — 여유 10°.
- 판정: 모든 하위 측정에 noninf. 하나라도 틀림 → 틀림, 모두 맞음 → 맞음.

### 주장 6. 후보 실행은 모두 건강하다
- 후보 실행마다: (가) 끝까지 돎(`stop` 빈 문자열, `t_end` = T); (나) 스텝 끝 음수 없음(`neg_end_cellsteps` = 0, `h_min_end_of_step` ≥ 0, 그리고 내가 본 모든 스냅숏과 끝 상태에서 젖은 칸 h ≥ 0); (다) `mass_err_max` < 1e-10; (라) `V_crumb` < 0.001 × (V0 + Vinj); (마) 끝 상태 Σh 가 V0 + Vinj − V_crumb 와 상대 1e-5 안에서 맞음(float32 저장이라 이 정도로만 확인).
- 판정: 모든 후보 실행이 모두 통과 → 맞음, 하나라도 못 하면 → 틀림. 대조도 같은 표를 참고로 낸다.

## 6. 알려진 한계
- 스냅숏 간격이 20 이라 그 사이에 생겼다 사라진 부스러기는 못 본다(1a 는 그만큼 후보에 너그럽다; crumb_cells 로 흔적만 본다).
- 점액 U 는 스냅숏 사이에만 젖었던 칸을 놓친다 → fresh 가 실제보다 높게 나오고 T_trap 이 늦게 잡힌다(주장 4 창이 늦어지는 쪽, 주장 2·3 창은 `t_scl` 로도 자른다).
- 문턱(두께 0.5, 0.3, 흐름 5%, 절단 3칸)은 데이터를 보기 전에 정한 것이고, 민감도를 함께 보고한다.
