## 3. 정의 (`verify/scripts/monitor.py`, `measure.py`)

- **조각(성분)**: 토러스 8연결 성분. 내가 쓴 `monitor.tlabel` (scipy.ndimage.label + 가장자리 합치기)을 쓴다. 모델의 `_torus_label` 은 쓰지 않는다
  (무작위 마스크 300개에서 같은 나눔을 내는 것은 확인했다).
- **갈라짐**: 젖은 셀의 성분이 2개 이상. 크기를 따지지 않는다 (외톨이 셀 하나도 갈라짐이다).
- **갈라진 시간 비율** `split_frac`: long 의 모든 스텝(스텝 1~20000)의 끝에서 갈라진 스텝의 비율.
- **바깥 부피** `vol_out`: 1 − (가장 큰 젖은 성분의 Σh) / (젖은 셀 전체의 Σh). 스텝마다. 실행마다 시간 평균과 최대.
- **큰 굵은 조각**: 굵은 셀 = 젖고 h ≥ 0.6 (관 두께의 상한 cap=0.5 에 맥동 10% 를 더해도 넘는 값, 즉 관이 아닌 몸).
  굵은 셀의 토러스 8연결 성분 가운데 Σh 가 몸 전체 Σh 의 10% 이상인 것. `big2` = 그런 조각이 2개 이상인 스텝의 비율.
  민감도로 h 문턱 0.3 / 0.45 / 0.6 × 비율 5% / 10% / 20% 를 모두 낸다 (판정은 0.6 / 10% 만).
- **얇은 막 셀** `thin`: 젖고 h < 0.3 인 셀의 수.
- **줄 셀** `line`: 젖은 셀 가운데, 둘레 8칸(가운데 빼고)의 젖은 칸들이 3×3 안에서 8연결로 2개 이상의 무리로 나뉘는 셀의 수
  (그 셀이 마르면 둘레가 끊긴다: 실, 레이스). 256가지 무늬의 표를 직접 만들어 쓴다.
- **늦은 때**: long 의 t ≥ 1500 (끝 2000). 그 구간의 모든 스텝의 평균.
- **먹이 닿음**: `metrics.json` 의 `t_touch` (먹이 원반에 젖은 셀이 처음 생긴 시각). `n_reached` = 닿은 먹이 수,
  `t_all` = 마지막 먹이에 닿은 시각 (하나라도 못 닿으면 T).
- **먹은 양** `eaten`: `metrics.json` 의 `Vinj` (먹어서 늘어난 부피, gain=1).
- **이주**: mig 의 `t_touch` (70 셀 떨어진 유인원 원반에 닿은 시각, 못 닿으면 400)와 `disp_toward`
  = 저장 상태(20 시간마다)로 따라간 h 무게중심의 마지막 이동을 유인원 방향(27°)으로 투영한 값.
- **건강** (실행마다):
  - 스텝 끝 음수 없음: `neg_end_cellsteps == 0` 이고 `h_min_end_of_step >= 0`.
  - 부피 오차 < 1e-10: 모델의 `mass_err_max` 와 내 점검 둘 다. 내 점검 = 먹이 없는 실행은 `series.npz` 의 스텝마다 Σh 와 처음 부피의 차의 최대,
    먹이 실행은 `log`(50 스텝마다)의 |V − V0 − Vinj| 의 최대, 모두 V0 로 나눈다. (모델의 값은 버린 부피를 되돌려 더하므로 내 점검이 더 엄하다.)
  - 버린 부피 없음: `V_crumb == 0` 이고 `crumb_cells == 0`.
  - 끝에 젖은 성분이 정확히 하나: `wet.npy` 를 내 표지기로.
  - 끝까지 돌았음: `stop == ''` 이고 `steps_done == T/dt + 1`.
- **부호 검정**: 같은 시드 쌍의 차이에서 같은 값은 빼고, "후보가 더 작다" 쪽의 한쪽 이항 검정.

## 4. 판정 문턱 (`verify/scripts/judge.py`)

### 주장 1 — long 에서 몸이 갈라지지 않는다 (long 쌍 10개 이상, 모두 끝까지 돌아야 판정)

- 1a 갈라진 시간: 후보 평균 ≤ 0.01 이고 후보 실행마다 ≤ 0.03 → 맞음. 후보 평균 > 0.05 이거나 어느 후보 실행이 > 0.20 → 틀림. 그 사이 → 판정 못 함.
- 1b 바깥 부피: 후보의 (실행별 시간 평균)의 평균 ≤ 0.001 이고 후보의 모든 스텝 최대 ≤ 0.01 → 맞음. 후보 평균 > 0.01 이거나 어느 후보 실행의 시간 평균 > 0.03 → 틀림. 그 사이 → 판정 못 함.
- 1c 큰 굵은 조각 2개 이상 (`big2`, h ≥ 0.6, 10%): 대조 평균 < 0.05 → 판정 못 함 (견줄 것이 없다).
  후보 평균 ≤ 0.5 × 대조 평균 이고 부호 검정 p ≤ 0.05 → 맞음. 후보 평균 > 0.8 × 대조 평균 → 틀림. 그 사이 → 판정 못 함.
- 주장 1: 셋 모두 맞음 → 맞음. 하나라도 틀림 → 틀림. 나머지 → 판정 못 함.
- 1a, 1b 의 대조 값도 함께 적는다 (대조가 원래 잘 안 갈라지면 "대조보다 낫다"는 말은 힘이 없다는 것을 보고에 쓴다).

### 주장 2 — 늦은 때 얇은 막 셀과 줄 셀이 대조보다 적다 (long 쌍 10개 이상)

- `late_thin`, `late_line` 각각: 후보 평균 < 0.9 × 대조 평균 이고 부호 검정 p ≤ 0.05 → 맞음. 후보 평균 ≥ 대조 평균 → 틀림. 그 사이 → 판정 못 함.
- 주장 2: 둘 다 맞음 → 맞음. 하나라도 틀림 → 틀림. 나머지 → 판정 못 함.
- 넓이로 나눈 비율(`late_thin_frac`, `late_line_frac`)도 적지만 판정에는 쓰지 않는다 (주장은 "수가 적다"이다).

### 주장 3 — 먹이 찾기와 굶은 이주가 나빠지지 않는다

시나리오마다 (food3, asym3, food4, mig). 실행이 빠지거나 끝까지 못 돌면 그 시나리오는 "unclear".
- 먹이 시나리오:
  - 닿은 먹이: 후보 합 ≤ 대조 합 − 2 → worse.
  - `t_all`: 쌍 차이(후보 − 대조)의 중앙 > 0.15 × 대조 중앙 이고 후보가 늦은 시드 ≥ 75% → worse. 앞 조건만 → unclear.
  - 먹은 양: 쌍 비(후보/대조)의 중앙 < 0.9 이고 후보가 적은 시드 ≥ 75% → worse. 앞 조건만 → unclear.
- mig:
  - `t_touch`: 위 `t_all` 과 같은 규칙.
  - `disp_toward`: 쌍 차이의 중앙 < −0.15 × 대조 중앙 이고 후보가 짧은 시드 ≥ 75% → worse. 앞 조건만 → unclear.
- 주장 3: 어느 하나라도 worse → 틀림. worse 없이 unclear 가 있으면 → 판정 못 함. 모두 ok → 맞음.
- 보조(판정에 쓰지 않음): bmet.py 의 food `pass` 수.

### 주장 4 — 후보 실행 모두 건강하다 (long 12 + food4 6 + food3 8 + asym3 8 + mig 8 = 42개)

- 위의 건강 다섯 가지를 42개 후보 실행 모두가 통과 → 맞음. 하나라도 실패 → 틀림. 빠진 실행이 있고 실패가 없으면 → 판정 못 함.
- 대조의 건강도 적는다 (판정에는 쓰지 않음).

## 5. 내 예측 (실행 전)

- 주장 1: 1a, 1b 는 맞음일 것이다 (90%). keep_conn=2 는 마르는 덩어리를 통째로 보므로, 마름 단계에서 찢어질 길이 거의 없다.
  대조는 long 에서 자주 갈라질 것이다 (갈라진 시간 0.3 이상, 70%). 1c 는 불확실하다: 후보가 실로 이어진 두 덩어리(아령)를 만들 수 있다.
  1c 맞음 50%, 판정 못 함 30%, 틀림 20%.
- 주장 2: keep_conn 이 마를 셀을 젖은 채 두므로 실(줄 셀)이 남을 수 있고, ret_h/ret_glob 이 그것을 거둔다. 어느 쪽이 이길지 모른다.
  얇은 막이 적음 55%, 줄 셀이 적음 45%. 주장 2 전체 맞음 35%.
- 주장 3: 맞음 60%. 가장 위험한 것은 food4 (먼 먹이 넷: 흐름 경쟁이 한 갈래를 말려 먹이 하나를 놓칠 수 있다).
- 주장 4: 맞음 65%. 가장 그럴듯한 실패는 버린 부피(V_crumb): crumb_dry 는 켜져 있고, 음수 셀(neg_dry, 색 제한 없음)끼리 붙은 덩어리 안쪽 셀은
  남는 이웃이 없어 부피가 버려질 수 있다. 그다음은 스텝 끝 음수(keep_conn 이 지킨 음수 셀의 이웃이 모두 0 이하일 때).
- 주장 밖에서 볼 것: 몸의 모양(실로 엮인 그물, 아령), 넓이, 이동 거리, keep_conn 이 지킨 셀 수, 끝 상태 그림.
