## 1. 코드 읽기 (f1.py, mgt.py) — 확인한 것
- 수축파: `th_eff = theta + (2π/λ)·(mimg(X−cen_u[0])·cos α + mimg(Y−cen_u[1])·sin α)`, `α = 2πt/T_rot` (T_rot=0 이면 α=0 고정, +x 방향 기울기).
  무게중심 `cen_u` 는 감김을 푼 h-무게중심(10스텝마다 최소 상(minimum image)으로 갱신). 기울기는 무게중심에서 N/2 떨어진 곳에서 톱니처럼 끊긴다(192² 에서 ±96셀).
  진폭 ε 은 그대로이고 위상 무늬만 바뀐다. 보고서 설명과 일치.
- `food_phase` / `food_dw`: 살아 있는 먹이 원반 안 셀의 수축 위상에만 더한다. 보고서 설명과 일치.
- `res_acc=2`: 배율 Hres 가 시간 상수 res_tau 로 h_res 까지 오름. `res_gate`: h ≥ res_gate·(직전 스텝 쉬는 두께)일 때만 오름. 일치.
- `bridge_keep`: 3×3 고리의 Yokoi 연결수(8연결) ≤ 1 이거나 인접 관 C < 1 일 때만 마름, 2×2 색 하나씩. 일치.
- `neg_dry`, `dry_weight="h"`: 음수 셀은 바로 마르고(유예·bridge_keep 무시), 부피(또는 부족분)를 남는 이웃의 두께에 비례해 나눔. 보존식 확인(Σ 몫 = h_i).
- 부피 오차: `|Σh − V0 − Vinj|/V0`. 주입은 `h[m] += gain·amt/n` 과 `Vinj += gain·amt` 가 짝이 맞는다. 유량 갱신·마름·젖음 모두 보존형. **계산이 맞다.**
- 멀티그리드 실행에서 직접 풀이 `solve()` 는 `check_every` 스텝마다 오차 계산에만 쓰이고 p 를 덮어쓰지 않는다. 부작용 없음.
- 구조를 손으로 심는 코드는 없다(초기 C=0, 새 간선은 D0·(1±0.3), 정적 간선 잡음 G). 손으로 넣은 것은 수축파와 food_phase/food_dw 뿐(보고서가 밝힘).
- 대조 쌍의 차이: params.json 을 비교하면 Y3_wave 대 Y3_base, Ym_wave 대 Ym_base 는 `wave_lambda`(100 대 0) 하나만 다르고(시드 1·2·3 모두), R_ph180 대 R_base 는 `food_phase` 하나만 다르다.
  V4_wave_gate 대 V4_wave 는 `res_gate`(와 진단용 neg_diag), Z3 의 2사이클·3사이클·직접 풀이는 `ncyc`·`solver` 만 다르다. 실험자 주장과 일치.
- 재현성: 실험자의 Y3_wave_s1 을 최종 코드(+내 옵션 2개, 기본값은 동작 불변)로 다시 돌리면 닿은 시각·면적·정맥 간선 수·hmin 이 자릿수까지 같다(chk_Y3_wave_s1).

  최종 규칙 묶음(수축파 + gate + 두께 비례 마름 + 3사이클, A3_final_s12): 스텝 안 −0.0041, 스텝 끝 음수 0, 경로 최소 C 506/768/355, 몸 0.987, 유량 오차 0.037/0.112/0.265.
- 긴 실행에서는 스텝 끝 음수 셀·스텝이 1만~3만으로 남는다(외딴 셀. 실험자도 밝힘). "0~1"은 대칭 배치 T=480 의 값이다.

## 13. 발견한 문제 (버그·보고 불일치)
모델 코드(f1.py, mgt.py)에서 결론을 바꾸는 버그는 찾지 못했다. 아래는 측정·보고 쪽 문제다.
1. **C1 표의 창 불일치** (5절): 594·434·286, 0.29/0.6, 0.52/7 은 "먹는 동안"이 아니라 실행 끝까지의 창. 먹는 동안 값은 134·464·194, 0.43/1.9, 0.79/31. 방향은 같다.
2. **시트 진폭의 표본 시각** (12절): 회전 위상에 묶인 한 시점 값. "0.053~0.060 대 0.069~0.071"은 수축파의 효과가 아니다.
3. **C5 의 2사이클 대 직접 풀이 비교** (10절): 시드 하나 + 창이 한 표본 어긋남. 새 시드 둘에서 차이 없음.
4. **무게중심 추적의 한계**: `centroid()` 는 몸이 격자 절반을 넘게 퍼지면 틀어진다(먹이 실행의 t>440: 30 시간단위에 −10 → −86 으로 뜀). metrics 의 `disp` 는 먹이 실행에서 쓸 수 없다.
   같은 무게중심을 쓰는 수축파의 위상 기울기도 그때 톱니 경계(±N/2)가 몸에 걸린다(Y3_wave_s1 t=480: 젖은 셀 463개). 분석 창(먹는 동안, 이주 t≤400) 밖이라 주장에는 영향이 없다.
   192² 격자는 먹이 셋 실행의 끝에서 몸이 격자를 반 바퀴 넘게 덮는다(면적 28%).
5. **유량 오차 중앙값 "0.05~0.08"은 대칭 배치의 범위**다. 비대칭 배치에서 0.10, 이주 한 실행에서 0.088, 낮게는 0.035 까지 나왔다.
6. 사소: `food_dw` 만 줄 때 `P['food_phase']` 가 [0,…] 로 덮어써져 params.json 에 남는다(동작 영향 없음). K_ramp30_s1 에는 hfood.npy 가 없어 상관 +0.94 는 R_base_s1 의 값이다.

## 15. 하지 못한 것
- 수축파가 왜 듣는지의 직접 측정(가로 유량 성분의 크기, 가로 가지의 생성 시각)은 하지 않았다. 6·7절의 결론은 방향을 바꾼 대조 실행에서 나온 것이다.
- 고정 가로 파는 시드 3개, 고정 세로 파와 먹이 둘 고정 파는 시드 2개, 민감도는 시드 1개(11)다.
- 256² 먹이 넷은 새 시드 1개씩이다. 유인장을 확산장으로 바꾸는 시험은 하지 않았다.
- 큰 격자(384² 이상)에서 수축파 + 먹이 규칙은 돌리지 않았다(실험자도 하지 않음).
