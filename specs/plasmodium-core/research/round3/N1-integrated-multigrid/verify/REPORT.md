# N1-integrated-multigrid 독립 반박 검증

상태: 진행 중 (시작 2026-11-13 06:15 UTC). 실험 폴더의 기존 파일은 고치지 않았다. 이 폴더(verify/)에만 쓴다.

## 검증 대상
담당자 판정 partial: "E9 MG 그대로는 발산, 질량 항을 과보정에서 빼면 수렴. 2사이클/스텝이면 유량 오차 중앙값 0.09~0.15, 음수 두께 0, 같은 부류의 형태(몸 길이 +8%, 끝점 −10% 의 체계적 차이), 1사이클은 불합격."

## 계획
1. 그림 5장 직접 확인 (m_dyn_final, m_time_s1, m_large_final, d_s1_mg2 최종, g_384_s1_mg2 최종).
2. n1.py 코드 읽기: 보고된 식과 일치, 손으로 심은 구조, 전역 연산 유무, 패스 수 계산.
3. 저장된 배열(C_edges.npy, wet.npy, h.npy ...)에서 네이티브 간선 그래프 지표를 따로 짠 스크립트(vgraph_indep.py)로 다시 계산. 문턱(C>4/10/30/100)을 바꿔 본다.
4. 새 시드(11, 12)로 직접 풀이와 mg2 를 다시 돌린다. n1.py 를 verify/n1v.py 로 복사하고 훅만 추가:
   - 매 스텝(시드 11) 유량 오차를 따로 짠 희소 풀이(splu, 자체 조립)로 계산 → 버스트 유무.
   - 두께 최솟값(0 으로 깎지 않은 실제 값), 잔차 = p–h 관계 위반 |h_new − h* − p/κ| 분포.
   - 같은 시각 체크포인트에서 직접 풀이와 mg2 의 정맥 위치 겹침(Jaccard).
5. E9 구성 그대로(mg_mass=scaled)의 동적 실행이 정말 발산하는지 1회.
6. 통과 기준 재판정, GPU 패스 수 재계산.
계산 예산: 합계 10분 이내, 프로세스 1개.

### 코드 확인
- 멀티그리드 경로(k_diag, k_resid, _jac1, k_coarsen, k_restrict, k_prolong_add, MG.vcycle)는 전부 9점 스텐실과 2×2 축소·확대다. 전역 연산이 없다.
- 멀티그리드 실행에서 희소 직접 풀이(solve_exact)는 오차 점검에만 쓰이고 상태로 되돌아가지 않는다(n1.py 467~474행). 연결 성분 라벨링(ndi.label)도 점검과 최종 지표에만 쓰인다.
- 웜스타트는 직전 스텝의 멀티그리드 해다(444행). 조대 연산자는 간선 가중치만 /1.5 하고 차폐(질량) 항은 자식 합 그대로다(k_coarsen 의 f, fm).
- 패스 수: 512², V(2,2), 최조 격자 Jacobi 4회면 사이클당 드로콜 7×7+4 = 53, 미세 격자 환산 8.33회. 2사이클 + 조대 연산자 재구성 7 = 113, 환산 17.0회. 보고와 같다.

### 통과 기준 재판정
1. 유량 오차 중앙값 ≤ 0.15: mg2 통과(새 시드 0.105, 0.105, N=384 0.135). mg1 불통과(0.258). E9 구성 그대로는 발산. 보고와 일치.
2. 음수 두께 0: 통과. 매 스텝 잰 젖은 셀 최소 두께가 0.08~0.13 이다(마름 문턱 0.15 바로 아래).
3. 형태가 직접 풀이의 시드 편차 안: 이동 거리, Spearman, 위상 잠금, 두께 진폭은 안이다. 정맥 간선·분기 수는 mg2 가 두 시드 모두 적었다(간선 -4%, -17%, 분기 -3%, -31%). 담당자가 보고한 "분기 -15%"와 같은 방향이다. 외삽 변형은 방향이 일정하지 않다.

### 남는 문제
- mg2 는 기준을 넘기지만 여유가 작다(384 에서 0.135~0.15, 버스트 최대 0.56~0.68). 0단계의 기본 구성은 mg2+외삽 0.5 또는 3사이클이 안전하다.
- 512² 는 담당자 실행 1회(T=300, 이주 전 단계, 기준선 없음)뿐이고 다시 돌리지 않았다. 768² 는 아무도 돌리지 않았다.
- 드로콜 수는 스텝당 약 136(512², 2사이클)으로 예산(약 60)의 두 배가 넘는다. WebGL2 실측은 없다.
- 음수 두께 0 은 E10 대표 설정에서의 결과다. N3 의 두꺼운 저장소 변형은 직접 풀이에서도 음수 두께가 나왔다.
