# 계획 D — 얇은 칸일수록 덜 흐름을 GPU 코어에 넣는다

> spec: `spec.md`의 규칙 3(`s_e`), 7차 표의 S3, "미해결 문제" 10의 마지막 줄. numpy 근거: `research/round7/S3-thin/` (작성자 보고, 독립 검증 `verify/`, 덧붙인 확인 `split/`)
> 상태: 사용자 확인 대기

## 무엇을 바꾸나

규칙 3의 간선 가중치다. 지금은 `W = G·(C + r)/L` 이라 거의 빈 칸에도 굵은 관이 그대로 흐른다. 그래서 칸이 가진 것보다 많이 빠져 두께가 음수가 된다.
바꾼 뒤에는 두 끝 가운데 얇은 쪽의 두께로 흐름을 줄인다: `W ← W · min(1, max(0, min(h_i, h_j)) / h_thin)²`, `h_thin = 0.15`.

numpy 결과 (지금 규칙 대 이 규칙):
- 스텝 끝 음수: 새 시드 먹이 실행 37개 가운데 대조는 33개에 남는다(실행마다 1~8스텝). 이 규칙에서는 37개 모두 0
- 전진, 정맥, 먹이 잇기, 젖은 넓이, 부피 오차, 풀이 오차: 구별되지 않는다 (독립 검증)
- 몸이 갈라져 있는 시간: 늘지 않는다 (새 시드 20쌍, 짝 차이 +0.015)
- 남는 것: 스텝 안 음수가 드물게 생긴다(음수 칸 말리기가 지운다). 몸 밖 작은 조각이 조금 는다

## 단계

**Step 1. numpy 기준 모델의 기본값과 기준 자료**
- `export_ref.py`의 관문 B 설정(`GB`)에 `thin_h=0.15`를 넣는다. 관문 A 설정(`GA`)과 모델 기본값(`DEF`)은 그대로 둔다(관문 A의 기록을 그대로 두기 위해).
- 먹이 스텝 일치 시험의 상태 덤프(`foodstate`, `food6state`, `foodfadestate`)를 새 GB로 다시 만든다.
  - 덤프마다 "s_e < 1 인 활성 간선 수"를 세어, 규칙이 실제로 걸리는 상태인지 적는다.
- `foodcrumbstate`(외톨이 셀 시험)는 `thin_h=0`으로 그대로 둔다. 이 규칙을 켜면 외톨이 음수 셀이 거의 생기지 않아 그 시험이 비게 된다.

**Step 2. GPU 구현**
- `PlasmParams`에 `thinH: number`(0 = 끔)를 넣는다.
  - `defaultParams`(관문 A)는 0이다. 관문 A의 산술을 비트 단위로 그대로 두기 위해서다.
  - `foodParams`와 관문 B의 시나리오는 0.15다.
- `rest.frag.glsl`: 간선 가중치(`oW`)를 만드는 줄에서, `#if {{THIN_ON}}`일 때 두께 텍스처에서 간선의 다른 끝 넷(+x, +y, +x+y, +x−y)을 읽어 `s_e`를 곱한다.
  - 텍스처 읽기 4번이 늘고, 드로콜 수는 그대로다.
  - 이 패스는 압력 풀이 전에 돈다. numpy와 같이 "스텝을 시작할 때의 두께"를 쓴다.
- 조대 격자의 연산자는 이 가중치에서 만들어지므로 따로 고칠 것이 없다. 0에 가까운 가중치가 numpy 다중격자를 망치지 않는 것은 확인했다(검증 S2). GPU는 Step 3에서 본다.

**Step 3. 시험**
- 먹이 스텝 일치 시험(`?test=parityfood`)을 새 덤프로 돌린다. 비교하는 것:
  - 젖은 마스크가 numpy와 완전히 같은지
  - 두께와 가중치의 차이가 기존 문턱 안인지
- 회귀: `?test=a0`, `?test=parity`(관문 A, 규칙을 끈 길)가 그대로 통과하는지, 드로콜 수가 그대로인지.
- 관문 B를 **모두** 다시 판정한다. 외톨이 셀(계획 C)과 달리 이 규칙은 굶은 실행에도 걸린다.
  - 시나리오 15가지, GPU와 numpy를 같은 시드로 나란히 돌린다(이름 꼬리 `_th`). 지난번 기준으로 GPU 3개씩 나란히 약 2시간이다.
  - `judge_b.py`로 B1~B7을 다시 낸다. 규칙 이전 기록과 나란히 적는다.
  - GPU와 numpy가 같은 결과를 내는지(관문 B의 (가))도 다시 본다.

**Step 4. 문서와 배포**
- `RESULT-B.md`에 "계획 D 이후"를 더한다.
- spec의 "GPU는 아직"을 고치고, B1의 판정 줄을 새 결과로 고친다.
  - B1의 "스텝 끝 음수 셀 0"을 넘으면 그렇게 적는다. 기준을 느슨하게 하자는 물음은 거둔다.
- 시험 페이지의 "먹이 셋" 돌려 보기에도 규칙을 켠다.
- 작업 브랜치 커밋 → `main` `--no-ff` 병합 → 배포 확인.

- 스텝 안 음수를 완전히 막는 장치. 지금은 음수 칸 말리기가 지운다. 드문 큰 음수(−0.275)의 길은 남아 있다.
- 관문 A 설정에서도 켤지. 켜면 관문 A의 기존 기록과 비트 단위로 달라진다.
- 속도 측정을 다시 할지. 텍스처 읽기 4번이라 휴대폰에서 측정의 흔들림 안일 것으로 본다. 필요하면 다음 측정 때 함께 잰다.
