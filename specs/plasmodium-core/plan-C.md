# 계획 C — 외톨이 셀 말리기를 GPU 코어에 넣는다

> spec: `spec.md`의 규칙 6 마지막 줄과 "미해결 문제" 10. numpy 근거: `research/round7/S1-split/` (7차 S1, 새 시드 25쌍)
> 상태: 사용자 확인(2026-11-20) → 구현·시험 끝. 결과는 `stage0/RESULT-B.md`의 "계획 C 이후"

## 무엇을 바꾸나

규칙 6(마름)의 마지막 줄이다. 마르는 후보 셀에 남는 젖은 이웃이 하나도 없으면, 지금은 그 셀을 말리지 않는다(넘겨줄 곳이 없어서).
그래서 몸이 떠난 자리에 음수 두께의 외딴 셀이 끝까지 남아, 먹이 실행에서 스텝 끝 음수가 수천 스텝 세어졌다.
바꾼 뒤에는 그런 셀도 말리고, 그 부피(음수면 부족분)는 버린다.

numpy 결과(새 시드 25쌍, 지금 규칙 대 이 규칙):
- 스텝 끝 음수가 있는 스텝: 먹이 실행 2922~5777 → 0~9, 굶은 실행 0 → 0
- 버린 부피: 실행마다 V0의 4e-4 이하
- 관문 B의 통과 여부: 25쌍 모두 같음

## 단계

**Step 1. numpy 기준 모델의 기본값과 기준 자료**
- `export_ref.py`의 관문 B 설정(`GB`)에 `crumb_dry=1`을 넣는다. 관문 A 설정(`GA`)과 모델 기본값(`DEF`)은 그대로 둔다. 이미 돌린 기록을 다시 만들지 않기 위해서다.
- 먹이 스텝 일치 시험용 상태 덤프를 새로 만든다. 외톨이가 실제로 마르는 순간이 시험 창에 들어오게 한다:
  - `ref_model.py`에 `crumb_from`(이 스텝부터 규칙을 켠다)을 더한다.
  - 지금 규칙으로 3790스텝까지 돌려 외딴 음수 셀이 있는 상태를 만든다.
  - 그 스텝부터 규칙을 켜고 +1, +10, +50스텝을 덤프한다(`foodcrumbstate`).
  - 상태에 외딴 셀이 실제로 있는지 덤프에서 센다.
- 먹이 덩어리가 없는 길도 하나 둔다(굶은 이주의 한 시점). 기존 시험과 같은 꼴이다.

**Step 2. GPU 구현**
- `PlasmParams`에 `crumbDry: boolean`을 넣는다.
  - `defaultParams`(관문 A)는 false다. 관문 A의 산술을 비트 단위로 그대로 두기 위해서다.
  - `foodParams`와 시나리오(관문 B)는 true다.
- `dry_confirm.frag.glsl`: `#if {{CRUMB_DRY}}`일 때 이웃이 없는 후보도 마르게 한다.
  - `dry_share`는 이미 이웃이 없을 때 몫을 0으로 낸다. 그러니 부피가 버려지는 것 말고는 바뀌지 않는다.
  - 드로콜 수는 그대로다.
- 버린 부피의 장부: 스텝 통계 축소(`reduce_stats`)에 "이번 스텝에 버린 부피" 채널 하나를 더한다.
  - 시험이 부피 보존을 `V − V0 − 먹은 양 + 버린 양`으로 본다.
  - 축소 출력에 빈 채널이 없으면 이 줄은 시험 쪽에서 상태 차이로 계산한다(덤프 비교용).

**Step 3. 시험**
- 먹이 스텝 일치 시험(`?test=parityfood`)에 Step 1의 새 덤프를 더한다. 비교하는 것:
  - 젖은 마스크가 numpy와 완전히 같은지
  - 두께 차이가 기존 문턱 안인지
  - 외딴 셀이 같은 스텝에 마르는지
- 회귀: `?test=a0`, `?test=parity`(관문 A, 규칙을 끈 길)가 그대로 통과하는지, 드로콜 수가 그대로인지.
- 관문 B를 일부 다시 판정한다. B1(음수·부피)과 직접 닿는 시나리오만 GPU와 numpy를 나란히 다시 돌린다:
  - food3 1~6, asym3 1~3, food4 1~3, food3_256 1~3
  - `judge_b.py`로 B1·B5 줄을 다시 낸다.
  - 나머지 시나리오(이주, 방향, 점액, 지속)는 외톨이가 거의 생기지 않으므로 다시 돌리지 않는다. 기존 판정을 그대로 두고, 그 사실을 적는다.

**Step 4. 문서와 배포**
- `RESULT-B.md`에 고친 뒤의 B1·B5 줄을 덧붙인다.
- spec "미해결 문제" 10의 "GPU는 아직"을 고친다.
- 시험 페이지의 "먹이 셋" 돌려 보기에도 규칙을 켠다.
- 작업 브랜치 커밋 → `main` `--no-ff` 병합 → 배포 확인.

## 정하지 않은 것

- B1의 "스텝 끝 음수 셀 0" 기준. 이 규칙으로도 먹이 실행에 한두 스텝짜리가 0~9번 남는다. 기준을 "끝까지 남는 셀 0"으로 바꿀지는 이 계획에 넣지 않았다.
- 관문 A 설정에서도 켤지. 굶은 실행에서는 외톨이가 실행마다 0~5개뿐이다. 켜면 관문 A의 기존 기록과 비트 단위로 달라진다.
